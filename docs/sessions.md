# 会话日志、恢复与上下文

日志按需开启。默认会话仍只保留在内存中；需要重启恢复时，在项目目录运行：

```sh
my-coding-agent --env .env --session 开发1
```

退出后使用同一工作区、模型、适配器和工具模式恢复：

```sh
my-coding-agent --env .env --resume 开发1
```

会话存于工作区 `.coding-agent/sessions/开发1.jsonl`。名称限 1–64 个字母、数字、下划线或连字符，不能使用系统保留名称；`--session` 不覆盖已有文件。目录被 Git 忽略，也不能通过模型文件工具读取。单次调用也可记录，但其工具模式为只读，恢复时须保持同一模式，例如交互恢复需加 `--read-only`。

## 记录什么

日志格式版本为 1，每行有递增序号和事件类型：身份信息、完整模型请求、模型响应、可恢复历史、确认操作开始及实际结果。请求记录包括实际选择的上下文和工具定义；响应保留工具调用 ID 和协议所需推理字段。推理不会作为终端消息显示。HTTP 认证头和 API 配置不写入日志；含当前已知 API Key 的内容会在记录前被拒绝。

日志含发送给模型的代码、对话和操作输出，应作为本地项目数据保存。未知凭据无法自动识别。此功能不加密日志、不自动上传，也不自动清除历史。`/clear` 只清空后续模型使用的上下文和待确认提案，旧日志记录仍保留。

每条记录同步写入并 fsync。模型请求先记录再发出，确认操作先记开始再执行，实际结果先记录再继续模型请求。写入或锁失效后停止后续请求与副作用，不悄悄降级为无日志模式。退出终端时先取消并等待当前操作结束，再关闭日志。日志上限 128 MiB，达到后需新建会话；当前完整历史仍驻留内存。

## 恢复和异常退出

恢复只接续成功历史及已记录的实际操作结果。已失败或未完成的模型请求保留在日志中，不变成成功回答；旧提案全部失效，须重新读取和提案。文件写入和命令都不会自动重放。

若只有确认操作的开始记录，缺少结束记录，实际副作用可能已经发生。恢复会补记 `unknown`，提示检查文件和进程，并禁止本会话继续确认写入或命令。`/clear` 不解除限制；核对实际状态后新建会话。模型仍可帮助读取和分析。

使用 proper-lockfile 独占打开日志。同一会话已有进程时拒绝第二个写入者；异常退出后，至少等待 10 秒让遗留锁过期，再恢复。正常退出会释放锁。不要用并发手工编辑日志的方式处理锁。

未完成的最后一行默认拒绝恢复。显式选择：

```sh
my-coding-agent --env .env --resume 开发1 --repair-session
```

程序先将完整原文件复制为带随机编号的 `.bak`，再移除未完成末行并恢复。完整行损坏、序号错误、工具调用配对错误、未知版本或身份不符均拒绝恢复，不猜测修复。不要删除原文件来掩盖未知操作结果。

## 上下文长度

`--context-chars` 或 `CODING_AGENT_CONTEXT_CHARS` 设置请求 JSON 的 UTF-16 字符预算，默认 48000，范围 4000–1000000。这是内部请求 JSON 的字符数，不是服务商 token 上限或精确计费估计；最终 wire 字段长度也可能不同。

请求过长时，从最早的完整用户轮次开始省略，保留工作区规则、当前输入及本轮完整工具调用和结果，并加入已省略条数的提示。实际裁剪后的请求写入日志，完整成功历史继续保留。不会拆散工具调用与结果，也不让模型猜测被省略的文件内容。当前轮次本身超限时返回 `CONTEXT_LIMIT`，需要缩小任务、减少读取内容、清空或提高预算。

这不是语义摘要；被省略的事实不会自动回忆。再次需要旧代码时重新读取。日志保留完整记录，但目前没有自动检索日志、日志轮转或全文压缩功能。

## 验证

`pnpm check` 覆盖恢复、锁、身份、版本、畸形数据、末行修复与备份、未知操作、密钥拒绝和完整轮次裁剪。`pnpm test:session:pty` 启动两个独立 CLI 进程，验证历史与轮数恢复及退出。`pnpm test:session:live` 通过真实 DeepSeek 读取临时标记，再从日志恢复工具历史并引用前文；另外测量同一合成历史裁剪前后的 prompt token。实际结果见[开发日志](development-log.md)。
