# 命令执行与测试反馈

交互模式的 `propose_command` 展示程序、逐项参数、工作目录和超时。确认内容后输入 `/run command-1` 执行；`/reject command-1` 丢弃。编号以实际预览为准，不能用 `/apply` 执行命令。模型提出命令本身不会启动进程。

```sh
my-coding-agent --env .env --workspace "D:/你的项目"
```

可输入“读取 package.json，提出运行单元测试的命令，等待我确认”。单次任务和 `--read-only` 不提供命令工具，`--no-tools` 关闭全部工具。

## 参数与执行

工具要求 `program`、字符串数组 `args`、相对目录 `cwd` 和 `timeout_ms`。参数最多 64 项，整体 JSON 不超过 16 KiB；超时为 100–120000 毫秒。工作目录须已存在且通过文件工具的路径规则，启动前再次校验。同时最多 10 个待确认命令，`/clear` 丢弃待确认项。

Agent 不自动解释管道、重定向或命令连接符。Windows 使用 cross-spawn 处理可执行文件与 `.cmd` 包装器，`pnpm` 等命令可正常解析。显式选择 shell 程序时，其参数由该程序解释。可执行文件在确认后从当前 PATH 或指定路径解析，提案不锁定程序文件版本。

命令使用用户账户权限，工作目录检查不限制进程访问其他目录、网络或凭据文件；这不是沙箱。只运行用户审阅过的前台命令，不支持后台服务和守护进程。子进程只继承 PATH、系统路径、临时目录、用户目录与语言等少量环境配置，不继承模型 API Key 或其他任意父环境。程序仍可自行读取本地文件和用户配置。

## 结果、超时与取消

合并 stdout/stderr，最多保留 16 KiB，超出标记 `truncated`；跨流顺序按接收时间，不保证与原程序逐字节顺序一致。当前按 UTF-8 解码；旧版 Windows 程序输出其他编码时可能出现乱码。已知模型 API Key 在回传前精确脱敏，任意其他敏感内容仍需用户审阅后决定是否运行相关命令。

结果包含实际程序、参数、目录、状态、退出码和有界输出。退出码 0、非零退出码和超时结果均交给模型，帮助分析测试是否通过；取消保留结果后停止当前模型请求。真实执行结果立即记入会话，后续模型失败不回滚命令造成的变化，也不会自动重试同一编号。

取消或超时请求终止所拥有的进程树并等待关闭：Windows 使用 taskkill，其他平台终止独立进程组。若无法确认清理，会报告 `unknown`，停止后续修改和命令确认；检查并关闭残留进程后重启会话。后台或脱离进程组的进程不在支持范围，不能把前台退出理解为所有外部副作用已结束。

## 验证

`pnpm check` 覆盖确认前不启动、拒绝、重复确认、目录变化、非零退出、输出截断、环境过滤、脱敏、缺失程序、超时、取消与历史保留。`pnpm test:tui:pty` 验证真实终端中的命令预览和执行结果。`pnpm test:commands:live` 让真实 DeepSeek 提出 Node 测试命令，显式确认入口仅执行临时夹具，再验证结果回传。实际计数见[开发日志](development-log.md)。
