# 文件修改与确认

交互模式提供 `propose_file`：模型先读取文件，生成完整新内容和 diff。提案不会写入文件；在输入区输入 `/apply edit-1` 才应用，`/reject edit-1` 丢弃。编号以实际预览为准。通过 PgUp/PgDn 看完整 diff 后再确认。

```sh
my-coding-agent --env .env --workspace "D:/你的项目"
```

先输入具体任务，例如“读取 README.md，补充启动步骤并提出修改”。可使用 `--read-only` 关闭修改提案，或 `--no-tools` 只对话。单次调用没有后续确认环节，因此仅提供只读工具。

## 提案和写入规则

`propose_file` 接收相对路径 `path`、完整 UTF-8 文本 `content`、`expected_sha256`。修改已有文件时，摘要必须与 `read_file` 的结果一致；新建文件使用 `null`，父目录须已存在。读取保留 BOM、CRLF 和结尾换行，模型应保留未要求修改的内容。新内容上限 64 KiB，预览上限 30000 字符，同时最多保留 10 个待确认提案。修改受只读工具相同的路径、凭据、忽略项和链接限制约束。

应用前重新检查原文件内容摘要和权限；文件已变化或新路径被占用时拒绝覆盖，需重新读取并提案。写入使用同目录临时文件，刷新后原子替换；新建使用不覆盖已有路径的创建操作。保留普通权限位，Windows ACL 按系统规则继承。当前不支持删除、创建父目录或多文件事务。

这些检查不能抵御另一进程在最后检查与替换之间恶意竞争，不是操作系统级沙箱。提交阶段失败会报告 `WRITE_UNCERTAIN`，必须先检查实际文件，再提出新修改。已处理编号不能重试执行。

## 取消、失败和历史

确认写入前可取消；已提交的写入不会回滚。实际操作结果立即加入会话，之后模型失败或取消也会保留。拒绝和失败结果本地返回，不额外请求 API；成功应用后，模型收到实际路径与新摘要，可继续解释或提出下一项修改。

提案只存在内存中，退出或 `/clear` 后失效。模型请求失败时，已显示的提案可继续通过编号确认；未确认提案不会自动应用。成功模型回答计入轮数，纯本地拒绝或确认失败不计入。显示层去除终端控制符，不改写文件或模型上下文。

## 验证

`pnpm check` 验证版本冲突、受保护路径、BOM/CRLF、新建、拒绝、重复确认、取消及模型失败后的实际结果。`pnpm test:tui:pty` 在临时工作区显示 diff、确认写入并检查真实文件。`pnpm test:editing:live` 使用本地 API，仅修改临时夹具，比较只读和修改工具定义的 prompt token；测量值见[开发日志](development-log.md)。
