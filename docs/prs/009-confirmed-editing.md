# 阶段 009：修改预览与确认写入

模型需要把代码建议落到文件，同时让用户先检查具体改动。此阶段在交互 CLI 提供 `propose_file`，展示 diff 和编号；用户输入 `/apply 编号` 后才写入，`/reject 编号` 丢弃。单次调用和 `--read-only` 保持只读。

写入前检查内容摘要与普通权限，使用同目录临时文件替换；保留原换行和 BOM。文件变化、路径被占用、受保护或忽略路径均拒绝写入。已确认操作结果独立于模型成功历史保留，防止模型失败后遗忘实际文件改动。每个编号只能处理一次，提交结果不明时显式报告。

阅读顺序：[使用规则](../editing.md) → [文件操作](../../src/tools/workspace.ts) → [提案工具](../../src/tools/editing.ts) → [会话](../../src/conversation.ts) → [测试](../../tests/editing.test.ts)。

验证：`pnpm check`（47 项测试）、构建后单次启动、`pnpm test:tui:pty --capture`、`pnpm test:editing:live`、文档链接与差异检查。真实 DeepSeek 使用临时文件完成读取、提案、显式应用和结果回传；只读工具首条请求 552 prompt token，修改工具 724，增加 172。这是功能上下文成本，不是性能提升。

限制：没有多文件事务、删除、父目录创建或进程沙箱；并发外部进程仍可能在最后检查与替换间竞争。提案不持久化，命令执行另行实现。
