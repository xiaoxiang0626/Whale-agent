# 逐个 PR 的开发路线

这是开发计划。当前可运行能力以 [README](../README.md) 和源码为准；每次只完成一个 PR，并在该 PR 中交付代码、中文技术文档和验证结果。

| 阶段 | 交付范围 | 验收条件 |
| --- | --- | --- |
| 001 | TypeScript 项目、CLI、模型接口、离线适配器 | 不需要密钥即可演示；能注入另一适配器；类型检查、测试和构建通过 |
| 002 | 可直接运行的 CLI 命令 | 本地注册后可使用 `my-coding-agent`；直接运行与 `--help` 均显示帮助 |
| 003 | 你的真实模型 API 适配器 | 配置本地凭据后能完成文本请求；错误、超时和取消可识别；有脱敏验证记录 |
| 004 | 交互式 CLI 与本次会话上下文 | 能持续输入、引用前文、清空、取消和退出；单次调用继续可用 |
| 005 | Agent 循环与只读代码工具 | 模型能请求列出和读取工作区文件；工具结果进入下一次模型请求；循环有步数上限 |
| 006 | 文件修改、diff 与确认 | 展示修改预览，经确认后写入；路径限制和原文件变更检查有测试 |
| 007 | 命令执行与测试反馈 | 用户明确允许后执行命令；处理工作目录、超时、取消和输出上限；结果回到模型 |
| 008 | 会话日志、恢复与上下文管理 | 重启后可恢复记录；模型可见内容有记录；异常退出和日志版本有明确处理规则 |

阶段编号用于组织需求，与 GitHub 自动分配的 PR 编号独立。产品以 CLI 形式交付，后续按用户实际提出的需求调整顺序。

## 每个 PR 的协作方式

先说明本次要解决的具体问题，再实现该范围，运行对应检查，并编写包含阅读顺序和验收方法的 PR 说明。每个 PR 完成自审且相关检查通过后，由开发者自行合入 `主分支`，再同步本地主分支继续处理下一个需求。检查失败、冲突或验证所需信息缺失时，先解决问题，不绕过检查合并。

分支名、PR 标题和说明统一使用中文。默认分支为 `主分支`，功能分支按 `功能/<阶段编号>-<中文需求名>` 命名，例如 `功能/001-基础框架`。代码标识符、命令和技术名称保留原文。

## 真实 API 接入前需要的信息

- 协议：例如 OpenAI Chat Completions、Anthropic Messages 或自定义 HTTP JSON。
- Base URL、模型名、认证头名称，以及是否需要其他请求头。
- 一份脱敏的请求和响应示例，或服务商 API 文档。
- 是否支持工具调用；文本请求接通后再据此确定工具循环的协议。

API Key 由用户在本地配置。私有服务的业务数据和凭据不进入测试夹具或 PR 说明。

MCP、多 Agent、插件框架和复杂压缩策略暂不安排到上述阶段；可在基本编码流程完成后按需要规划。
