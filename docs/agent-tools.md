# 只读 Agent 与工具循环

模型可以请求列出和读取工作区文件，再基于真实工具结果回答代码问题。工具仅操作文件系统，不执行文件内的指令。

```sh
my-coding-agent --env .env --workspace "D:/你的项目" "先读取 README.md，再解释项目入口"
```

默认工作区为启动目录，`--workspace` 或 `CODING_AGENT_WORKSPACE` 可指定其他目录。已读取的文本会随上下文发送给配置的模型服务。纯文本对话可加 `--no-tools`。

## 工具与输出

| 工具 | 参数 | 结果 |
| --- | --- | --- |
| `list_files` | `path`；可选零起算 `offset`、`limit` | 当前目录可见项、类型、总数与下一页偏移 |
| `read_file` | `path`；可选一起算 `start_line`、`max_lines` | UTF-8 原文、行区间、总行数、下一页、sha256 与 BOM 标记 |

路径均相对工作区，根目录用 `.`。目录默认最多返回 100 项、最高 200 项；文本默认读取 100 行、最高 200 行，文件不得超过 256 KiB，单次文本内容最多 20000 字符。单行超过该长度会失败；更多内容可按 `nextLine` 分页。预期失败以带错误码的 JSON 返回模型，模型可更换路径或参数后继续。

终端显示工具名与简短结果，例如 `[工具] read_file：读取 src/app.ts，30 行`。工具正文进入模型上下文，终端最终回答仍由模型生成；模型的推理字段不会显示为消息。

## 路径规则

工具只接收相对路径，禁止父目录跳转、绝对路径、符号链接、目录联接和硬链接文件。工作区内根目录与逐层 `.gitignore` 的规则生效，文件访问前校验真实路径，打开后核对文件标识。

`.env*`（`.env.example` 除外）、常见私钥文件、`.git`、`.ssh`、云凭据目录、`node_modules`、`dist`、本地原图归档等受保护项不会提供给工具。二进制与无效 UTF-8 文件不作为文本读取。路径检查不构成操作系统级进程沙箱。

## 循环、取消和上下文

助手返回函数调用后，Agent 按顺序执行本批工具，把每个结果与调用 ID 放入消息，再请求模型。每个 API 响应最多 8 个调用，每轮工具总数最多 32 次；`--max-steps` 设置模型请求上限，默认 12、范围 1–100。达到最后一次请求后不再执行新的工具，避免完成工具后缺少最终回答机会。

成功后，当前用户输入、助手工具调用、结果与最终回复一起加入内存历史。失败、超限或取消不改变此前成功历史；取消会阻止后续工具以及迟到结果提交。`/clear` 清空成功历史与待确认提案；当前没有会话持久化。[确认操作](editing.md)的实际结果立即记录，不随模型失败回滚。

DeepSeek 思考模式要求在工具请求中回传 `reasoning_content`。项目保留该字段用于协议转换，详情参见[模型 API](model-api.md#协议)。

## 离线和真实验证

```sh
my-coding-agent --provider mock "演示列出 src"
my-coding-agent --provider mock "演示读取 README.md"
pnpm check
pnpm test:tui:pty
pnpm test:agent:live
```

前两条不会调用模型 API，但文件工具会实际执行。真实检查需已配置本地 `.env`，使用临时夹具，不把真实项目内容、密钥或推理正文写入仓库。测试范围和测量值见[开发日志](development-log.md)。
