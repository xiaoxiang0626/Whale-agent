# 阶段 010：命令确认与测试反馈

文件修改后需要真实测试反馈。此阶段增加 `propose_command`，展示具体程序、参数、目录与超时；用户输入 `/run 编号` 后才执行。命令输出和退出码进入模型上下文，非零退出码也能继续分析，不能用文字回答替代实际测试结果。

执行器限制输出、过滤继承环境、精确脱敏已知 API Key；处理启动失败、超时、取消与进程树清理。实际结果先记录，再继续模型请求；重复编号不再执行，进程清理未知时阻止后续副作用。使用 cross-spawn 支持 Windows 包装器，不提供进程沙箱。

阅读顺序：[使用与限制](../commands.md) → [命令工具](../../src/tools/commands.ts) → [执行器](../../src/tools/process.ts) → [会话](../../src/conversation.ts) → [测试](../../tests/commands.test.ts)。

验证：`pnpm check`（51 项测试）、构建后启动、`pnpm test:tui:pty --capture`、`pnpm test:commands:live`、文档与差异检查。真实模型完成 5 次请求，临时 Node 测试退出码 0；首条消息只声明工具定义时，由 724 增至 939 prompt token，增加 215。没有性能提升结论。

范围：前台命令、一次性确认和有界反馈。会话持久化与恢复在下一阶段实现；后台进程、完整环境复现和操作系统隔离未交付。
